PRACTICE / 01 — CLARIFY

Ask before you build.

“Build me a Git client.” Three decisions change the product.

01

Inspect changes,
or change the repo?

Inspect only.

02

Can repository content
leave the machine?

Not when the app runs.

03

What does
“read only” protect?

Files, index and refs.

Ask what changes safety, scope or evidence.

Illustrative product choices. A cloud coding agent is a separate data boundary.

PRACTICE / 02 — PRESERVE THE AGREEMENT

The task ends.
The requirement stays.

DURABLE PRODUCT INTENT

Inspect local changes
without risking your work.

Behavior
Staged, unstaged and untracked changes
Safety
Preserve files, index and refs
Privacy
No off-device repository content
Non-goals
Commit, reset, checkout and push
KEEP CURRENT

Intent, constraints,
acceptance expectations

KEEP TEMPORARY

Plans, task state,
implementation attempts

Change behavior deliberately.
Update the agreement with it.

Power is not direction.

The seven-layer hierarchy is an editorial framework. Its arrow means upstream influence, not measured contribution or the best next investment. Hardness estimates concern application-side engineering with existing models and tools—not training a model from scratch. The ordering and estimates are not validated by these sources.

Intent, acceptance evidence and constraints form a durable agreement. That agreement may be short. Model capability, tools, context and feedback remain necessary; no layer repairs every failure. Model size is not a task-performance score. Security rules apply throughout: this is not a prompt-authority hierarchy.

Direction is not capability.

The alternative is minimum sufficient structure: improve the current bottleneck, and scale process to uncertainty, consequences, reversibility and coordination needs—not application size alone. The decision matrix is illustrative, not a validated policy. A routine change in a large repository is not automatically low-risk.

The minimal-agent and Agentless examples challenge unnecessary orchestration, not the need for a task, an environment or tests. Agentless is a historical coding-benchmark comparison, not a current leaderboard claim. No benchmark was reproduced for these slides.

The June 2026 v2 of Evaluating AGENTS.md reports no general task-success improvement from additional repository context files and higher inference cost in its tested Python coding settings. Its current benchmark name is CTXbench. Do not interpret nonsignificant performance differences as proof of a general reduction in success, or “no extra context file” as “no intent.” The study acknowledges the usefulness of specific non-standard instructions; it is not grounds to remove safeguards.

None of this directly evaluates IDD or proves results for every application. The pair's synthesis is: Keep the intent. Earn the extra structure.

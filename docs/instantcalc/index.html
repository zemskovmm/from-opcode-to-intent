02 / workflow definitions

The same product, four preparation paths

Initial clarification and answers precede building. The deliberate refinement budget varies by workflow; question/answer interactions are counted as separate measured receipts, not extra refinement rounds.

APP1 Zero
No deliberate refinement rounds after initial clarification.
APP2 One
One deliberate refinement round before implementation.
APP3 Five
Five deliberate refinement rounds, R1 through R5.
APP4 Five + IDD
Five rounds, then genuine IDD on the target after R5: intent work and an intent freeze before baseline building.

44 deliberate refinement rounds across the sixteen cells. First builds, operator continuations, model repairs, evaluations and terminal dispositions remain separate in the process trees. A terminal node records closure, not necessarily success.

Historical control differences prevent a clean workflow ablation. 125 malformed CLI plugin overrides establish a control defect; they prove neither actual plugin use/contamination nor effective isolation. The corrected repair03 epoch is different, and generic inventories in resumed sessions differ. Global-read isolation remained instruction-only residual exposure.

03 / quality detail

Keep the dimensions and evidence gaps visible

B: eight baseline core cases. C: eight feature core cases. R: eight robustness probes. Feature B regression rechecks the original baseline behavior. F01–F04 are separate conformance statuses. A numerator counts observed passes; the remainder can be failed, blocked, not run or undisclosed.

The UI rubric reports five individual 0–2 observations in this order: readability, pointer/touch controls, keyboard/focus, layout/scroll reachability, consistency/discoverability. These operator-scored observations have imperfect blinding. They are not summed into a global score.

05 / methods & limits

What these measurements can support

Time: observed intervals

Per-cell totals sum elapsed seconds from unique complete phase receipts only, bound by event ID to the frozen phase/process CSV: 151 of 154 receipts. The three incomplete intervals remain in the downloadable history and are excluded from these sums. Each row shows its complete/total receipt coverage.

These are generation/interaction intervals, not pure model generation time. Parallel work shared one host. Intervals can overlap; their sums are neither elapsed project wall clock nor isolated speed. Operator, helper and evaluator overhead is unmeasured and excluded; its coverage is unknown.

Estimates: a known subtotal

$18.28016324 across 119 known-estimate events. Across all 154 raw receipt pairs there are 992 unique emitted response IDs; 954 belong to the 152 complete-telemetry records. These response counts cover more than the 119 priced events. All actual billed charges are null/unknown. Declared API-equivalent rates are not invoices.

35 receipts have no estimate: 33 with full telemetry but unsupported Astra pricing and 2 with partial telemetry excluded. A further interrupted Sol APP1 build has finalized priced telemetry: it belongs to the known estimate subtotal but not the complete-interval time sum. Accounting and timing intentionally have different eligibility rules.

Quality: source-bound evidence

Final typed run outcomes and the 32-row quality matrix are authoritative. Core, robustness, regressions, conformance and UI observations remain separate. First and repaired source commits, repair counts and selected case statuses are retained in the curated JSON. Source-suite success is not UI proof.

Framework disclosure and actual observation are different. The canonical event field for observed framework is unknown for these runs; this page does not infer a framework from undisclosed F01. Evaluation is of a web preview, not native platform qualification. Evaluator focus, selection and click interception errors are not app defects without attribution.

Interpretation: a descriptive pilot

One observed run per model/workflow cannot establish a universal winner, model ranking or causal IDD benefit. Model/operator histories, control epochs, imperfect blinding and exhausted evaluation budgets differ. Blocked evidence stays in the denominator.

The canonical derived projection contains the historical parent-link and paused-status corrections; the raw history remains unchanged. Missing Astra APP3 turn completion is trace coverage uncertainty, not automatic application failure. Historical sealing discrepancies were disclosed, not rewritten: segment18 matched 694/695; segment19 matched 784/785 after a qualified budget change.

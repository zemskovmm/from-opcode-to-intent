# B09 Constraints comparison and experiment caveats

Supporting data. Attached to 09 Freedom is a bug - constraints narrow the options.

The PDF proposes several genuine outputs from the same vague customer-form request, followed by several outputs from a request tied to existing components and explicit constraints. This could make the solution-space argument visible.

These screenshots have not been generated for this plan. Collect and label actual examples before treating the display as evidence; report the task, context, model, and selection method. A few chosen screenshots are an illustration, not a controlled performance result.

The PDF also refers to randomized software-design experiments where framing desires as requirements led to more practical but less original designs. That source has not been independently checked in this revision. Keep the precise empirical claim off stage until the full study and its conditions are checked.

Goldratt's Theory of Constraints belongs, if used, to the bottleneck analogy. It should not be offered as psychological proof that restrictions increase creativity.

The defensible main-stage point is modest: constraints change which results count as acceptable. They can also exclude good answers if the constraint itself is wrong.

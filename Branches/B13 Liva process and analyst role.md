# B13 Liva process and analyst role

Supporting data. Attached to 13 Intent is the new working unit.

Proposed Intent Driven Development / Liva process:

1. A person describes the outcome, possibly by voice.
2. AI asks questions about goals, scenarios, constraints, risks, and consequential omissions.
3. The transcript is reconciled into an agreed requirements/intent document. Unresolved decisions remain visible.
4. Divide the work into coherent intent areas with explicit shared constraints and interfaces.
5. Agents implement bounded changes, delegating technical subtasks when useful.
6. Validate behavior against agreed criteria and examine the evidence.
7. Maintain intent, implementation, and important technical decisions together as the product changes.

The primary authored description emphasizes what and why, rather than merely narrating how the current code happens to work. It does not abolish implementation documentation, test review, operations, or security analysis.

This is where analytical and product judgment becomes central. A good question can prevent a large plausible implementation of the wrong thing. That is a proposed mechanism of value, not a measured productivity result.

Stage allocation: about one minute inside the final 110-second beat, then the Brooks callback and closing line. Avoid explaining an entire agent framework here.

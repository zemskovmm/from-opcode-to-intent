# B10 Context and executable boundaries

Supporting data. Attached to 10 Reference beats description.

A reference to a working screen can carry conventions more efficiently than a long restatement. It only helps if the agent retrieves the relevant material and distinguishes reusable conventions from accidental details.

The PDF's implementation-oriented context sources include:
https://www.anthropic.com/engineering/building-agents-with-the-claude-agent-sdk

These links are background pointers from the PDF's context discussion; this revision does not claim to benchmark the associated tools.

Your proposed documentation should maintain the goal, constraints, scenarios, and why they matter. Reference existing implementation contracts where helpful. Keep executable checks as boundaries on acceptable outcomes, not as proof that every unstated intention has been met.

A failed test is evidence of disagreement with a specific expected behavior. A passed test can coexist with a wrong product requirement or an incomplete test suite. Agree the acceptance criteria independently of the generated implementation.
